# Supabase Edge Functions

Backup copies of the edge functions deployed to Supabase project `qpaouhptaeldqthxabnk`.
These are **snapshots for version control / disaster recovery** — the running code lives in
Supabase. If you change a function in the Supabase dashboard, re-export it here.

| Function | What it does | Trigger |
|---|---|---|
| `ask-claude` | Powers the ✨ Ask Claude page. Sends pre-aggregated ops data (+ optional images) to the Claude API. | Called by the app |
| `send-daily-digest` | Emails the daily operations digest (P&L, BD alerts, BBM stock) for D-2. | Cron, 6 AM Jakarta |
| `weekly-insight` | Emails a strategic weekly briefing generated by Claude. | Cron, Sunday evening |
| `morning-briefing` | Emails a curated business/policy news briefing from RSS feeds. | Cron, 7 AM Jakarta |
| `parse-monitoring` | Reads a photo of the client's MONITORING REPLANTING table via Claude vision. | Called by the app |

## Secrets (NEVER commit these)

These live only in Supabase → Edge Functions → Secrets:

- `ANTHROPIC_API_KEY`
- `RESEND_API_KEY`
- `SUPABASE_SERVICE_ROLE_KEY`
- `SUPABASE_URL`, `SUPABASE_ANON_KEY`
- `RECIPIENT_EMAIL`, `FROM_EMAIL`

## Re-deploying

Via the Supabase dashboard (Edge Functions → pick one → Edit → Deploy), or with the CLI:

```bash
supabase functions deploy <name> --project-ref qpaouhptaeldqthxabnk
```

## Keeping these in sync

There is no automatic sync. After editing a function in Supabase, copy the new source
back into the matching folder here and commit, so this backup stays current.
